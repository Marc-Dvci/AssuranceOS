# Security policy

AssuranceOS is a governed AI-native internal-audit platform, published with a
live demonstration deployment. Reports about either the code or that deployment
are welcome.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting: **Security → Report a
vulnerability** on this repository. It opens a private advisory visible only to
you and the maintainer, so nothing is disclosed while it is being fixed. Please
do not open a public issue for a security problem.

Include what you did, what happened, and what you expected. A request and its
response, or the run id printed by whichever script you used, is usually enough
to reproduce. There is no bounty. This is maintained by one person, so an
acknowledgement may take a few days.

## Scope

In scope:

* this repository, including the signed release artefacts under `agents/`,
  `audit-packs/`, `tests-library/` and `release/`, and the verification scripts
  that check them;
* the hosted demonstration API and its evaluator surface at `/judge`;
* the **evaluator sandbox**, which is the surface worth the most attention. It
  accepts credentials for a reviewer's own systems, stores them in Google Secret
  Manager, and lets a bounded connector read from a provider the reviewer names.
  It is described in the README and its guards are tested in
  `tests/test_evaluator_sandbox.py`. Anything that lets a caller name a secret
  outside the `assuranceos-eval-` prefix, reach a host outside the per-provider
  allowlist, address a tenant other than the one derived from the workspace id,
  or leave a workspace's credentials behind after deletion, is a vulnerability.

## Not vulnerabilities

These are known and deliberate, so a report about one will be closed as working
as intended.

* **The evaluator token is published and read-only.** It carries `viewer` plus
  two narrow permissions for replaying proofs that mutate nothing. It is meant to
  be shared. Reaching a write path with it is very much in scope; possessing it
  is not.
* **The demonstration tenant is invented.** The Asteria company does not exist
  and its corpus is generated by `scripts/build_demo_corpus.py`. Personal data
  found inside it is synthetic. One document deliberately carries a prompt
  injection payload, which the platform is built to detect and contain.
* **Scanner findings declared in `security/codeql-exclusions.toml`.** Each entry
  states why it is not a defect and names the tests that hold the reasoning up.
  A report showing one of those entries is wrong is a real report, and welcome.
* **The Explorer** at the repository homepage serves recorded responses and no
  backend. Every screen says so.

## Supported versions

The `main` branch is the supported version. Fixes land there rather than in
backports.
